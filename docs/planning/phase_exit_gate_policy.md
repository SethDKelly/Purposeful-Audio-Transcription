# Phase Exit Gate Policy

## Status

Accepted as the mandatory planning policy for all future phases.

---

# Rule

Every numbered phase must end with a mandatory exit review and consolidation subgroup before the next numbered phase begins.

A phase is not complete until its exit review is complete.

---

# Required gate name

Use this pattern:

```text
<PHASE>-<FINAL> — Phase <PHASE> Exit Review and Consolidation
```

For Phase 002, the required gate is:

```text
002-I — Phase 002 Exit Review and Consolidation
```

The letter may change by phase length, but the final subgroup must clearly be the phase exit review and consolidation.

---

# Purpose

The exit gate prevents planning drift by requiring each phase to consolidate decisions before the next phase starts.

It must answer:

- What was accepted?
- What was rejected?
- What was deferred?
- What terminology changed?
- Which documents became authoritative?
- Which documents were superseded?
- Which risks remain open?
- What is the next phase?
- Is the next phase allowed to start?

---

# Required outputs

Each phase exit review must include:

1. accepted decisions
2. updated authority order
3. terminology changes
4. deferred decisions
5. risks and unresolved questions
6. documents added or updated
7. documents superseded or flagged for reconciliation
8. readiness assessment for the next phase
9. recommended next phase sequence
10. explicit exit criteria result

---

# Exit criteria

A phase exit review is complete only when:

- all phase subgroup outputs are listed
- all accepted decisions are consolidated
- deferred questions are explicit
- conflicting/stale documentation is identified or updated
- the next phase is named
- a yes/no readiness decision is made

---

# Planning invariant

No future phase may start from scattered subgroup notes alone.

The phase exit review is the bridge between one phase and the next.
