# 000 — Concept Reset Charter

## Purpose

Reset the application design so that concept design, not the current implementation, becomes the source of truth.

The current implementation is valuable. It proves that transcription, transcript preparation, evidence indexing, analysis modules, reports, cases, React UI, AWS deployment, worker execution, and cost controls can work. However, the product definition has drifted.

The repository began from audio transcription, but the deeper product is conversation analysis, reflection, evidence, longitudinal understanding, and private reasoning over sensitive transcripts.

## Charter Statement

The current implementation is a prototype and reference implementation.

It is not the product specification.

The product specification will be rebuilt from concepts first.

## Current Product Hypothesis

The application is a secure conversation analysis and reflection system.

It analyzes transcripts, which may be derived from recordings, using evidence-based psychological, behavioral, therapeutic, cognitive, and relational lenses.

It helps users reflect on:

- communication patterns
- emotional reactions
- behavioral tendencies
- cognitive patterns
- potential biases
- relational dynamics
- therapeutic reflection points
- longitudinal changes over time

It must avoid:

- diagnosing people
- assigning personality disorders
- adjudicating abuse as fact
- proving intent
- replacing therapy
- making legal or clinical determinations
- treating speculative hypotheses as established truth

## Design Authority

After this reset, the authority order should be:

```text
Concept design
→ Product philosophy
→ Domain model
→ Security/privacy model
→ Analysis philosophy
→ Implementation architecture
→ Code
```

The code should serve the concepts, not define them.

## Initial Non-Negotiables

- Evidence traceability
- Confidence calibration
- Non-diagnostic discipline
- Safety-aware framing
- Ephemeral audio by default
- Encrypted retained transcripts
- Personal low-cost operating mode
- Future enterprise path without near-term enterprise complexity
- User control over retention
- Structured reasoning over chat-like output

## Exit Criteria

The concept reset is complete when:

- the product premise is clear
- the primary concepts are named and defined
- core tensions are identified
- security and retention are conceptually resolved
- cost posture is formally represented
- analysis boundaries are explicit
- current implementation can be refactored against the concept model
